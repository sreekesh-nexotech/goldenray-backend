# Deviations from PLAN.md and the standard

| # | Where | Deviation | Reason |
|---|---|---|---|
| DV-1 | §2.1 accounts_user.employee_id | The link lives on `hr_employee.user` (OneToOne) instead of `accounts_user.employee_id` | accounts is platform core and must not import hr (dependency direction) |
| DV-2 | §2.6 quotations_quotation.agreement_id / site_inspection_id | Links are held on the dependent side (`agreements_agreement.quotation_version`, `site_inspections_inspection.quotation_version`) | avoids circular app dependencies; reads resolve through reverse relations |
| DV-3 | §2.6 agreements_agreement.site_inspection_id | Stored as `source_type`/`source_uid`; the FK lives on `site_inspections_additional_work_item.agreement` | site_inspections depends on agreements, not the reverse |
| DV-4 | §6.2 `/bom/**` "no shim" | `/legacy/bom/api/calculate/` is shimmed with byte-parity to the old `BomCalculator` | the website quotation page (`frontend/src/services/bomService.ts`) calls it directly |
| DV-5 | §3.1 legacy "same paths" | Django serves old contracts only under `/legacy/…`; nginx rewrites the old public URLs to `/legacy/…` | keeps the application URL space strictly versioned |
| DV-6 | §2.3 inventory tables | Implemented in a dedicated `inventory` app | the plan lists tables but no owning app |
| DV-7 | §2.1 core_outbox_event | Five extra columns: `dedup_key` (partial unique, idempotent emit), `claimed_until` (drainer lease, set before dispatch; an expired lease makes the row claimable again), `next_attempt_at` (exponential retry backoff, 60 s × 2^(n-1), capped at 1 h), `parked_at` (poison pill after 5 failed or abandoned claims; `drain_outbox --requeue-parked [--id N]` re-drives it), `delivered` (handlers that already succeeded, never re-run on retry). `processed_at` is written only once every handler succeeded | the standard's outbox rules (§7.2: idempotency by unique constraint, claim before dispatch without double-fire, poison-pill guard) need state the PLAN table does not carry; marking rows processed at claim time lost every event of a drainer killed mid-batch (F-FIX) |
| DV-8 | §3.1 throttles | Extra scope `token_refresh` (300/15min per client IP) for `auth/refresh/` and `auth/logout/` instead of `login` (10/15min) | every active Studio user refreshes every 15 min, often from one office NAT or the BFF host; sharing the login budget would sign whole offices out |
| DV-9 | §2.1 audit_log.actor_id | `actor_id` is an indexed bigint without a database FK constraint (the Django relation uses `db_constraint=False`, `DO_NOTHING`) | an `ON DELETE SET NULL` action would rewrite rows of an append-only ledger (and blocks `TRUNCATE accounts_user`); users are only soft-deleted, so the reference never dangles |
| DV-10 | §2.1 documents_render_job | Two extra columns: `payload` (jsonb, the frozen document payload whose sha256 is `payload_sha256`) and `asset_id` (FK→media_asset, SET_NULL; the private PDF) beside `file` | the Celery message carries only the job uid, so a lost message or a dead worker is re-run from the row by the sweeper; the asset FK lets `media.usage` refuse deleting a rendered PDF; `file` stays for X-Accel without a join |
| DV-11 | §2.8 company_profile | `address` is five typed columns (`address_line`, `address_locality`, `address_region`, `postal_code`, `country_code`) and `notification_recipients jsonb` is `lead_notification_emails`/`application_notification_emails` (varchar[]) + `notify_on_new_lead`/`notify_on_new_application`; every other CMS `SiteSettings` and `bom.QuotationSettings` field is a typed column too (`default_meta_description`, `careers_*`, `quotation_offer_*`) | the legacy settings are typed; importers and the `/legacy/bom/api/quotation-settings/` shim map them field for field (docs/decisions/foundation-f3.md), and JSONB is reserved for validated documents |
| DV-12 | §5.2 redis | Two Redis services: `redis` (cache, `allkeys-lru`, no persistence) and `redis-broker` (Celery, `noeviction`, AOF) instead of one instance with two DB indexes | eviction policy and persistence are per instance in Redis; one instance cannot evict cache keys while never evicting broker messages |
| DV-13 | §3.1 staff surface | `media/download/<token>/` and `documents/download/<token>/` live under `/api/<version>/` but authenticate by their signed token alone (no JWT) | browsers follow these URLs from `<img>` tags and download links, which cannot send an Authorization header; the short-lived signature (10 min; single use for documents) is the capability, issued only to callers who passed the permission check |
| DV-14 | §3.1 staff surface / CLAUDE.md `BaseAPIView` | `documents/jobs/<uid>/` and `…/download-url/` are `IsAuthenticated` views that authorize in `documents.access.ensure_can_view` (the kind's registry permission → 403, then record visibility → 404) instead of `HasModulePermission`; they are the only such exemptions besides auth self-service and DV-13, listed in `core.checks.STAFF_VIEWS_WITHOUT_MODULE_PERMISSION` (system check `core.E006` fails any other staff view without module permissions) | the required permission depends on the job's kind/object type (quotations.view, attendance.export, …), known only after loading the job |
| DV-15 | §2.8 seo_fields | The mixin keeps the legacy CMS field names and lengths (`seo_title` 255, `meta_description` text, `noindex` bool) plus the plan's `og_title`/`og_description`; `robots` is expressed by `noindex` | lossless migration of existing CMS SEO data; the Studio already speaks these names |
| DV-16 | §3.2 Admin role (`settings.edit`) | Changing the `SMTP` integration (`settings/integrations/`) needs a Super Admin besides `settings.edit`; Admins keep TWILIO/BUNNY and read access | whoever controls the SMTP relay reads every password-reset link, a Super Admin's included — the plan keeps Super Admin accounts out of an Admin's reach ("everything except `users.manage` on Super Admins") |
| DV-17 | §2.8 sitepages_page, sitepages_page_text_slot, sitepages_page_image_slot | `sitepages_page` carries the legacy `route` (live-unique; the key the website and FAQs use), `description`, `group`, `is_protected`, `sort_order` beside `slug`/`title`/`status`/`template`, plus `verified_at`/`verified_by`; text slots add `guidance`, `max_length`, `sort_order` and `kind` = PLAN's SHORT_TEXT/RICH_TEXT/MARKDOWN ∪ the legacy LONG_TEXT/URL/EMAIL/PHONE; image slots add `label`, `guidance`, `sort_order` | every legacy column needs a home and the public contract is keyed on `route`; `verify` is a registry action on `pages`/`faqs` and needs its stamp |
| DV-18 | §2.8 faqs_faq, faqs_category | `faqs_faq` adds the legacy `section` and `archived_at` and `verified_at`/`verified_by`; `category_id` (PROTECT) is nullable; `faqs_category` adds the legacy `description` and `is_active` | lossless import of the CMS FAQs (all 100 seeded FAQs have no category; several pages carry more than one FAQ block) and the `faqs.verify` action |
| DV-19 | §3.3 `pages/{slug}`, `faqs?page=&category=` | Public FAQs take the page's route as `route` (`page` accepted as an alias) and return the legacy `{data, meta}` payload with `id` = uid; public pages are also served by `pages/?route=` with the legacy `{data: …}` envelope | `page` is the pagination parameter on every other list; byte-for-byte payload parity with the legacy CMS lets the website and the `/legacy/` shim switch without code changes |
| DV-20 | §3.4 Website content | Staff endpoints beyond the list: `pages/<uid>/{unpublish,archive,restore,verify,preview}/`, `faqs/<uid>/{publish,unpublish,archive,restore,verify,preview}/`, and `career-page/…` (the career page through the `career_page` grant); there is no DELETE on pages or FAQs | the legacy statuses (draft/published/archived) and preview endpoints must keep a home now that status is never PATCHed; the registry grants `verify`; the HR role holds `career_page` but not `pages` |
