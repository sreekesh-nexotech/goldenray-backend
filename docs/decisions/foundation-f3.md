## Decisions not spelled out in the PLAN

1. **Types come from the bytes.** Pillow (with `pillow-heif` for HEIC) opens and verifies images; PDF needs the
   header and an `%%EOF` trailer; `.doc` must be an OLE2 file with a `WordDocument` stream; `.docx` a ZIP with
   `[Content_Types].xml` and `word/document.xml`. The client's filename and Content-Type are ignored and the
   storage key's extension follows the content. Limits per kind: IMAGE/PHOTO jpeg/png/webp/heic ≤ 15 MB,
   DOCUMENT pdf ≤ 20 MB, RESUME pdf/doc/docx ≤ 10 MB (private only), SIGNATURE png ≤ 2 MB (private only); size is
   checked before reading (413 `file_too_large`), images above 50 MP are refused (`image_too_large`).
2. **Public images never publish a location.** A *public* image carrying EXIF GPS data is re-encoded without its
   metadata (orientation applied, ICC profile kept) before it is stored; `captured_at` is read first. Private
   originals are stored byte-for-byte.
3. **Storage before transaction.** The bytes are written before the database transaction opens (a Bunny PUT never
   holds row locks); a failed row write deletes the stored object; a storage outage is 503 `storage_unavailable`
   with nothing written. Deletion is a soft delete; the stored objects are removed after commit by a retried task.
4. **Usage guard = live references.** `media.usage.register(model, field)` (FK, one-to-one or M2M). Delete is
   refused while a *live* row references the asset; references held only by soft-deleted rows are reported but do
   not block. Registered so far: `documents.RenderJob.asset`, the seven `CompanyProfile` asset fields.
5. **Reserved folders.** `media.folders.reserve(prefix)` hides a context's files (rendered documents today;
   resumes, employee and inspection photos later) from the media library entirely — list, detail, edit, delete,
   signed URLs and uploads — so holding `media.view` never exposes a resume or an issued agreement. The owning
   context serves them with its own checks.
6. **Signed URLs.** Media: `TimestampSigner` object `{asset uid, checksum prefix, variant}` with a media salt,
   10 minutes, reusable until expiry (an `<img>` may load twice), dead once the asset is deleted/replaced.
   Documents: `TimestampSigner` over a `documents_download` row uid with a documents salt; the row is consumed by
   one conditional `UPDATE … WHERE used_at IS NULL AND expires_at > now()`, so concurrent requests cannot both
   download. Forged → 403 `signature_invalid`, expired → 410 `link_expired`, used → 410 `link_used`. Every private
   response is `private, no-store`, `nosniff` and CSP-sandboxed; with `USE_X_ACCEL` nginx streams the file from the
   `internal` `/media/private/` location.
7. **Document access follows the record.** `documents.access`: each kind has a default registry permission
   (QUOTATION → `quotations.view`, AGREEMENT → `agreements.view`, INSPECTION_REPORT → `site_inspections.view`,
   ATTENDANCE_REPORT → `attendance.export`, PUBLISH_REPORT → `pricing.view`); owning apps register per
   `object_type` a rule with a `visible(user, object_uid)` check. Without one, only `all`-scope users or the
   requester see the job (403 without the permission, 404 when not visible).
8. **Render pipeline.** `request_render(kind, object_type, object_uid, template, language, payload, user,
   reuse=False)` validates (kind, en/ml/hi, `<app>.<model>`, template exists, JSON object ≤ 1 MB), stores the
   canonical payload + sha256 and enqueues on commit. The task claims only a QUEUED job (`SKIP LOCKED`), renders,
   stores the PDF as a PRIVATE DOCUMENT asset in `documents/<kind>`, marks DONE with the page count, and emits
   `documents.render_completed` / `documents.render_failed`. Chromium start failures and storage outages are
   transient (job back to QUEUED, 3 retries with backoff); template/content errors fail the job with the error.
   The sweeper re-enqueues QUEUED jobs untouched for 10 minutes and fails RUNNING jobs older than 15 minutes.
   Playwright runs with JavaScript disabled and blocks every request except `https://` hosts in
   `DOCUMENTS_ALLOWED_ASSET_HOSTS`, so payload values can never make the renderer fetch internal URLs.
   `DOCUMENTS_CHROMIUM_EXECUTABLE` points Playwright at a preinstalled Chromium when its own is absent.
9. **Integrations through the platform.** `core.integrations.get_config(key)` is the platform's only view of
   `company_integration` (the company app registers the resolver in `ready()`; the platform never imports it).
   No caching: one indexed read per upload/e-mail/OTP, so edits apply immediately and decrypted secrets never sit in
   Redis. Bunny's `storage_endpoint` is restricted to Bunny's own storage hosts (the access key cannot be sent
   elsewhere). A stored SMTP integration only replaces a *delivering* SMTP backend — dev/test backends are never
   overridden.
10. **Company profile.** One live row (unique index on a constant); created on the first staff read; the public
    endpoint never writes (it serves defaults until the row exists). Brand assets are validated per field (logo,
    Open Graph image and offer banner must be public images; the signature a SIGNATURE). The legacy quotation offer
    semantics are kept exactly (`offer_is_active`: enabled, titled, today within the optional dates; Malayalam
    falls back to English; the uploaded banner wins over the URL).
11. **Bank accounts.** The first account is primary automatically; `make-primary/` moves the flag in one
    transaction; the primary cannot be deleted while others exist. Responses carry `account_number_last4` and a
    masked number only.
12. **Deployment.** Two api services (`api-a`, `api-b`) rather than `replicas: 2`, so the release script can restart
    them one at a time and wait for each health check; nginx upstream servers use `resolve` (nginx ≥ 1.27.3) so a
    recreated container is found without a reload. Migrations run only through the one-off `migrate` service as
    the owner role, straight to Postgres (not PgBouncer). The docker network is pinned to `172.28.0.0/16`
    (`TRUSTED_PROXIES`, `/healthz` allow-list).
13. **Legacy routing (DV-5).** `deploy/nginx/legacy/groups.conf` maps every §6.2 URL to a group;
    `switch.conf` (ops-managed copy on the VM) sets each group to `shim` (→ `/legacy/<old path>` on the api),
    `old` (→ the legacy containers; the CMS without its `/studio-api` prefix) or `gone` (404). Studio/admin/internal
    groups (`*_other`) are never shimmed. `core/tests/test_deploy.py` runs the real nginx configuration against
    mock upstreams and checks both switch states.

## Hand-over notes

* **Uploads from other contexts**: call `media.services.assets.upload(user=…, file=…, visibility=…, kind=…,
  folder="<your reserved folder>", allow_reserved=True)` and reserve the folder in your `AppConfig.ready()`
  (`media.folders.reserve("careers/applications")`); register every FK to `MediaAsset` with
  `media.usage.register(Model, "field")`. Embed assets in responses with `media.serializers.MediaAssetRefSerializer`
  (public URL only). Private files you serve yourself: `media.services.delivery.private_file_response(key, …)`.
* **Documents**: ship `templates/documents/<kind>/<lang>.html` extending `documents/base.html`; call
  `documents.services.jobs.request_render(...)` inside your service transaction; register
  `documents.access.register("<app>.<model>", module=…, action=…, visible=…)`; listen to
  `documents.render_completed` if you track the PDF. Download links only via
  `documents.services.downloads.signed_url(job, user=…, version=…)`.
* **Company data in documents**: read `company.services.profile.get_profile()` /
  `bank_accounts.primary_account()` in the owning service and put what the template prints into the frozen payload.
* **Twilio (leads)**: `core.integrations.get_config("TWILIO")` → `account_sid`, `verify_service_sid`, `auth_token`.
* **Cache**: public payloads that embed media depend on the `media` namespace (bumped on every media write).
* **Ops report**: register sections with `core.ops_report.register("<name>")(fn(since) -> dict)` (HR: agent
  offline hours, unknown ADMS devices).
* **Tests**: media/documents tests point `PUBLIC_MEDIA_ROOT`/`PRIVATE_MEDIA_ROOT` at `tmp_path` (see the
  `conftest.py` in those apps); `media.tests.files` builds real JPEG/PNG/WebP/HEIC/PDF/DOC/DOCX bytes; the
  Playwright test is marked `playwright` and runs whenever a Chromium can be launched.
